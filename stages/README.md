## 이사 비용표 — "효율"을 숫자로

세계에 법 하나를 심는 원가는 얼마인가. 단계마다 실측해 적는다.
**앱 코드**는 `*.py`·`*.html` 에서 `tests/`와 마이그레이션을 뺀 것,
줄 수는 `git diff <이전 태그> <이 태그> --shortstat` 기준이다.

| # | 켜진 법 | 앱 코드 | 마이그레이션 | 테스트 | 문서 |
|---|---|---|---|---|---|
| 0 | (범용 법이 딸려온다 — 학생은 모른다) | 15파일 +453 | 3개 (+162) | +69 · 4개 | +204 |
| 1 | 격상 + 권한(`change_refund`) | 16파일 +661 −15 | 1개 (+18) | +152 · 9개 | +129 |
| 2 | 없음 — 이미 켜진 법을 **인식**만 | 0 | 0 | +212 · 10개 | +298 |
| 3 | 없음 — DB 제약을 **실측**만 | 0 | 0 | +86 · 5개 | +208 |
| 4 | 도메인 법 3개(`REFUND-001`·`REFUND-002`·`ORDER-001`) | 5파일 +270 −47 | 1개 (+18) | (start에 포함) · 12개 | +16 |

### 4단계 — 이사 비용 (`stage-04-start` → `stage-04-done`)

> **프롬프트 세 문장을 코드로 옮기는 데 앱 코드 5파일 · 270줄 추가 · 47줄 삭제
> + 마이그레이션 1개(18줄)가 들었다.** (테스트·문서 제외)

```bash
git diff stage-04-start stage-04-done --stat
```

새로 생긴 것: `orders/verdict.py`(판정 계약) · `orders/rules.py`(임계값·규칙 ID) ·
`agent/templates/agent/denied.html`(409 화면). 고친 것: `orders/models.py` · `agent/views.py`.

읽는 법 두 가지.

1. **비싸다** — 자연어 세 문장이 코드 270줄이 됐다. 27줄이 아니라 270줄이다.
2. **싸다** — 그 270줄이 뷰로 오든 shell로 오든 MCP로 오든 **항상** 지켜진다.
   프롬프트 세 문장은 AI가 협조할 때만 지켜졌고, 실제로 협조하지 않았다(카드 ⑤⑥).

2·3단계의 앱 코드 0줄도 같은 표에 있어야 의미가 산다 —
**이미 켜져 있던 법을 알아보는 데 드는 코드는 0줄이다.**
8단계 끝에 "세계 하나 = 총 N줄"로 결산한다.

## 태그 규약

- 단계마다 `stage-NN-start`(결함이 심어진 시작 상태)와 `stage-NN-done`(법이 켜진 완료 상태) 두 개.
- `stage-NN-done`은 곧 `stage-(NN+1)-start`와 같은 커밋일 수 있다. 그래도 태그는 둘 다 붙인다.
- 0단계만 예외 — 시작 상태가 빈 저장소라 `stage-00-start`가 없다.
- **코드 변경이 없는 단계는 `-done` 하나만 붙인다.** 해부·실측만 하는 단계(2·3단계)는
  애플리케이션 코드를 고치지 않으므로 시작 상태와 완료 상태의 앱 코드가 같다.
  그 단계의 테스트는 이전 단계 완료 상태에서 이미 통과한다 — 새 법을 켜는 것이 아니라
  이미 켜져 있던 법을 테스트로 붙잡아 두는 것이기 때문이다.
  이때 `stage-NN-start`는 만들지 않고, `stage-(NN-1)-done`이 그 자리를 대신한다.
- 히스토리 재작성 금지. 이전 단계 코드를 고쳐야 하면 **최신 커밋에서 고치고 태그만 옮긴다**.
- 태그를 옮기면 아래 이력 표에 반드시 한 줄 남긴다.
