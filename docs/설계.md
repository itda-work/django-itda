# django-itda 설계 — 첫 코드(v0.1) 사양

> 정체·비목표는 [README.md](../README.md), 근거는 [벤치마킹-MCP-생태계.md](벤치마킹-MCP-생태계.md) §7.3·7.4.
> 이 문서는 **첫 코드의 범위와 계약**이다. 사양 입력은 첫 사용자 itda-django 의 실접속 관찰
> 두 차례(`examples/itda-django/stages/live-실접속.md` "관찰 기록 2026-09-06" 1차·2차)다.

## 0. 한 줄

Django 서비스 함수가 돌려주는 `(판정, 결과)` 를 **한 모양의 도구 결과**로 옮기고, 그 호출을 **궤적**으로 남기고,
그 도구들을 **`manage.py mcp_stdio`** 로 Claude Code/Desktop 에 붙인다. 판정은 한 줄도 하지 않는다 — 판정은
사용자의 도메인 코드(`Refund.decide/apply`, `Order.mark_paid`)가 한다.

## 1. 범위 — 관찰이 요구한 것만

| # | 관찰 입력 | 이 사양에서 |
|---|---|---|
| 1 | 임시 어댑터가 202 를 다른 모양으로 조립해 `outcome` 을 떨어뜨렸다(발견 1, 2차 재현) | **결과 매핑은 한 모양**. `kind`·`outcome` 은 1급 필드. HTTP 코드별 조립 없음 |
| 2 | DENY = 도구 오류, ESCALATE = 구조화 결과 — 실접속에서 그대로 작동 | 유지. 오류 문장에 규칙 ID·대안을 싣는다 |
| 3 | 승인 핸들은 `check_refund` 폴링으로 충분했다 | ESCALATE 결과에 `handle`(조회 도구 이름 + 대상 ID). Tasks 는 안 한다 |
| 4 | `approve_refund` 가 보이고 403 으로 막혔다 — 관찰 지점으로 유효 | 권한 검사는 항상, **목록 필터는 옵션**(`visible_only`, 기본 꺼짐) |
| 5·6 | shell 승인도 admin 승인도 장부가 없다(발견 3: admin action 은 `LogEntry` 0건) | 궤적 모델 `ToolCall` + `record()`. MCP 경로는 자동 기록, admin 경로는 7단계가 `record(via='admin')` 로 호출 |
| — | in-process 로 도니 잠금 실패를 503 으로 번역하던 미들웨어가 없다 | `is_lock_failure` 추출 → 도구 오류 "잠시 후 다시" (`retry_after`) |

**만들지 않는다(이번에)**: Streamable HTTP 브리지, 세션 쿠키 인증, Tasks/elicitation, OAuth, 권한=가시성 기본 켜기,
`itda_mcp_inspect`. 첫 사용자가 지금 소비하지 않는다.

**바꾸지 않는다**: `examples/itda-django/orders/verdict.py` 등 학생 코드. 패키지는 판정 객체를 **덕 타이핑**으로 받는다
(`kind`·`rule_ids`·`reason`·`alternatives` 속성 + `as_dict()`). itda-django 의 `Verdict` 가 그대로 맞는다. 재수출로
바꾸는 것은 8단계(도구면 대체) 때 한다.

## 3. 판정 계약 — `django_itda.verdict`

itda-django `orders/verdict.py` 의 `Verdict`·`Outcome` 을 **일반화만** 해서 옮긴다(문서 문장 포함).

- `Verdict(kind, rule_ids=[], reason='', alternatives=[])` frozen dataclass. `ALLOW/DENY/ESCALATE`, `STATUS_CODE`
  `{ALLOW:200, DENY:409, ESCALATE:202}`, `status_code`, `as_dict()`, `from_dict()`(모르는 열쇠는 버린다).
- `Outcome(state, subject=None)` — `NOTHING/QUEUED/COMMITTED/ALREADY/REPLAYED`. itda-django 의 `refund` 필드는
  `subject` 로 일반화. `committed` 프로퍼티.
- `VerdictLike` `typing.Protocol` — `kind`·`rule_ids`·`reason`·`alternatives` + `as_dict()`. 매핑은 이것만 요구한다.

## 4. 결과 매핑 — `django_itda.results`

도구가 세계에 무엇을 시켰든 **답의 모양은 하나**다.

```python
{
  "call_id": "…",                 # 궤적 상관 ID (uuid4 hex)
  "kind": "ALLOW|DENY|ESCALATE",
  "outcome": "NOTHING|QUEUED|COMMITTED|ALREADY|REPLAYED",
  "rule_ids": [...], "reason": "...", "alternatives": [...],
  "handle": {"check_tool": "check_refund", "id": 1, "status": "proposed"} | None,   # ESCALATE 일 때
                                  # 도구가 objects['handle'] 로 필드를 보탤 수 있다 —
                                  # {"check_tool": "get_order", "id": 4, "status": "pending",
                                  #  "url": "http://…/pay/4/<토큰>/", "expires_at": "…"}
  ...objects                      # 도구가 실은 대상 객체 dict (예: "order": {...}, "refund": {...})
}
```

- `tool_result(verdict, outcome_state, *, call_id, handle=None, **objects) -> dict`
- `ToolDenied(Exception)` — `verdict` 를 들고 다닌다. `str()` 은 임시 서버 `_denied` 와 같은 문장:
  `세계가 거부했다 [REFUND-001@v1] — <reason> / 대신 할 수 있는 것: a; b`. 권한 거부는
  `ToolDenied.forbidden(reason)` — `세계가 거부했다 — 권한 없음: <reason>` (rule_ids 없음, `kind` 없음 — 판정이 아니다).
- `ToolBusy(Exception)` — `retry_after` 초. 문장은 itda-django `BUSY_REASON` 그대로. 판정 필드를 싣지 않는다(판정한 적이 없다).
- **판정→예외 규칙**: 실행 도구(`query=False`)에서 `kind == DENY` 면 `ToolDenied`. 조회 도구(`query=True`)는 무엇이든
  결과로 돌려준다(질문에 답을 안 하는 것은 판정이 아니다). `decision`(escalated/settled/rejected) 같은 요약 키는
  **만들지 않는다** — `kind`·`outcome` 이 그 어휘다.

## 5. 도구 선언 — `django_itda.tools`

```python
from django_itda.tools import Toolset, tool
toolset = Toolset(name='itda-world', instructions=텍스트)

@toolset.tool(perm='orders.add_refund', handle_tool='check_refund')
def propose_refund(actor, order_id: int, amount: int | None = None, reason: str = '고객 요청',
                   request_id: str | None = None) -> ToolReturn: ...

@toolset.tool(perm='orders.view_refund', query=True)
def check_refund(actor, refund_id: int) -> ToolReturn: ...
```

- 도구 함수의 첫 인자는 항상 `actor`(Django `User`). 나머지 시그니처(타입힌트·기본값·docstring)는 그대로 MCP 스키마가 된다
  — 스키마 생성은 fastmcp 것을 쓴다(§7).
- 반환 `ToolReturn = tuple[VerdictLike, str(outcome state), dict(objects)]`. `handle` 은 `Toolset` 이 만든다:
  `kind == ESCALATE` 이고 `handle_tool` 이 선언돼 있으면 objects 의 `handle_subject`(기본 `'refund'`) 에서 `id`·`status` 를 읽는다.
  조회 도구는 `(verdict, state, objects)` 또는 `dict`(판정 없는 순수 조회 — `kind`·`outcome` 없이 objects 만) 둘 다 허용.
  도구가 `objects['handle']`(dict) 로 **핸들 필드를 보탤 수 있다** — 자동 핸들 위에 병합하고 objects 에서는 뺀다(`pop`).
  사람이 여는 URL 이 그 첫 사례다(itda-django 6단계 결제 링크 `url`·`expires_at`). `kind != ESCALATE` 면 꺼내서 버린다.
- `Toolset.call(name, actor, **args) -> dict`:
  1. `call_id` 발급, `started_at`.
  2. 권한: `actor.has_perm(spec.perm)` 아니면 `ToolDenied.forbidden(spec.forbidden_reason)` — 기본 문장
     `'{name} 을(를) 부를 권한이 없다'`, 선언에서 `forbidden_reason='AI 직원은 제안할 수 있지만 확정할 수 없다'` 로 덮는다.
  3. `spec.fn(actor, **args)` 실행. `OperationalError` 가 `is_lock_failure` 면 `ToolBusy`. 그 외 예외는 그대로 올린다(500 은 500 이다).
  4. 매핑(§4). 실행 도구 DENY 면 `ToolDenied`.
  5. **어느 갈래든** `trajectory.record(...)` 한 행(§6) — 성공·거부·busy·예외 모두. 기록은 `finally` 가 아니라 갈래마다 명시(무엇을 기록했는지 읽히게).
- `Toolset.specs(actor=None, visible_only=False)` — 도구 목록. `visible_only=True` 면 `has_perm` 으로 거른다(기본 꺼짐, 8단계 소재).
- `Toolset.tool` 은 `perm=None` 도 허용(권한 검사 없음)하되 itda-django 는 전부 perm 을 준다.

## 6. 궤적 — `django_itda.models.ToolCall`

append-only. 도구면의 호출 한 번이 한 행이다. 도메인 전이의 장부(7단계 `ledger`)와는 **다른 층**이고 `call_id` 로 잇는다.

| 필드 | 형 | 뜻 |
|---|---|---|
| `call_id` | `CharField(32, unique)` | 상관 ID. 결과의 `call_id` 와 같다 |
| `tool` | `CharField(100)` | 도구 이름 |
| `actor` | FK `AUTH_USER_MODEL` null, `SET_NULL` | 자리 |
| `via` | `CharField(20)` choices `mcp/api/admin/shell` | 어느 문으로 왔나 (발견 3 — admin 경로도 이 열에 남긴다) |
| `arguments` | `JSONField` | 호출 인자(그대로) |
| `kind` / `outcome` | `CharField(20, blank)` | 판정·결과. 권한 거부·busy·예외는 빈 값 |
| `rule_ids` | `JSONField(list)` | |
| `reason` | `TextField(blank)` | 판정 사유 또는 오류 문장 |
| `error` | `CharField(20, blank)` choices `forbidden/denied/busy/exception` | 갈래 |
| `started_at` | `DateTimeField` | |
| `duration_ms` | `PositiveIntegerField` | |

- `trajectory.record(**fields) -> ToolCall` — `create()` 한 줄. 트랜잭션 밖(도구 실행이 롤백돼도 호출 사실은 남는다).
- admin: `ToolCallAdmin` 읽기 전용(`has_add/change/delete_permission` False), list `started_at·tool·actor·via·kind·outcome·error`,
  필터 `tool·via·kind·outcome·error`, 검색 `call_id·reason`.
- `Meta.ordering = ['-started_at']`, verbose_name '도구 호출'.

### 6-1. 도메인 장부와 잇는 방법 — 호출 문맥 (v0.2, 2026-09-07)

도메인 코드는 요청도 도구도 모른다. 그래서 "어느 문·어느 호출" 은 **문이 열릴 때 문맥에 묶고**, 장부를 적는 쪽이 읽는다.

- `django_itda/context.py` — `contextvars.ContextVar` 하나. `bind_call(call_id, via, actor=None)` 컨텍스트 매니저,
  `current_call() -> CallContext(call_id, via, actor)`. 묶인 것이 없으면 `CallContext('', 'shell', None)` — shell 이 기본인 것이
  정직한 기본값이다(아무 문도 안 열렸는데 도는 코드는 사람이 직접 부른 것이다). 중첩은 안쪽이 이기고, 나가면 바깥이 되살아난다.
  `contextvars` 라서 `sync_to_async(thread_sensitive=True)`(어댑터의 도구 래퍼) 경로에서도 따라간다 — 스레드 로컬이면 거기서 끊긴다.
- `Toolset.call` — 권한 검사 **뒤** `spec.fn` 실행을 `bind_call(call_id, via, actor)` 로 감싼다. 권한 거부는 본문에 닿지 못하므로 문맥도 열리지 않는다.
- `django_itda/middleware.py:CallContextMiddleware` — 요청마다 `call_id` = `X-Request-ID` 헤더(하이픈을 벗긴 16진 32자 이내만) 또는
  `uuid4().hex`, `via` 는 `settings.ITDA['VIA']` 접두사 표에서 **첫 일치**(없으면 `'web'`). 응답 헤더 `X-Call-ID` 로 되돌려 준다(관찰용).
  `ATOMIC_REQUESTS` 와 무관하다.
- **`actor` 는 묶지 않는다.** 토큰 인증이 뷰 데코레이터 안에서 일어나 미들웨어 시점엔 자리를 모른다 — 자리는 문맥이 아니라 **명시 인자**로 받는다.
- **헤더를 믿는다 — 형식만 검사한다.** 클라이언트가 남의 ID 를 붙일 수 있다. 그것을 막는 것은 이 층의 일이 아니다.

첫 사용자의 배선: `MIDDLEWARE` 에 `WorldBusyMiddleware` 다음,
`ITDA['VIA'] = {'/api/': 'api', '/admin/': 'admin', '/agent/': 'console', '/orders/': 'console', '/pay/': 'customer'}`.

## 7. 어댑터 — `django_itda.adapters.fastmcp` · `manage.py mcp_stdio`

- `build_server(toolset, actor_provider) -> FastMCP` — `Toolset.specs()` 마다 fastmcp 도구를 등록한다. 등록 함수는 원 함수의
  시그니처에서 `actor` 를 뺀 것을 갖는다(`inspect.signature` 로 새 시그니처를 만들어 `__signature__`·`__annotations__`·`__doc__` 을
  심는다). 호출 시 `actor_provider()` 로 자리를 얻어 `toolset.call(name, actor, **kwargs)`. `ToolDenied`·`ToolBusy` →
  `fastmcp.exceptions.ToolError(str(exc))`. `instructions=toolset.instructions`.
- **fastmcp 임포트는 이 모듈에만.** `fastmcp` 가 없으면 이 모듈 임포트 시점에 `ImportError` 에 설치 안내(`uv sync --extra fastmcp`).
- `manage.py mcp_stdio [--token-env WORLD_TOKEN]`:
  - settings `ITDA = {'TOOLSET': 'agent.live.tools.toolset', 'AUTHENTICATE': 'accounts.models.APIToken.authenticate'}` 를
    `import_string` 으로 푼다. `AUTHENTICATE(raw) -> User | None`.
  - 환경변수(기본 `WORLD_TOKEN`)를 읽어 `AUTHENTICATE` 로 자리를 한 번 얻는다. 없거나 틀리면 `CommandError`(문장은 임시 서버의
    "세계에 들어갈 열쇠가 없다…" 를 따른다). 얻은 사용자를 `actor_provider` 로 고정한다(프로세스 = 자리 하나).
  - `build_server(...).run()` (stdio). stderr 에 한 줄 `django-itda mcp_stdio — toolset=<name> actor=<username>`.
  - **stdout 에 아무것도 찍지 않는다** — stdio 전송이 stdout 이다.

## 8. 첫 사용자 배선 — `examples/itda-django`

이 절은 패키지가 아니라 예시 프로젝트의 변경이다. 학생 코드(`orders/`·`accounts/`)는 건드리지 않는다.

- `config/settings.py`: `INSTALLED_APPS += ['django_itda']`, `ITDA = {...}`(§7).
- `agent/live/tools.py`(신규): 도구 7개를 `Toolset` 으로 선언. 본문은 `orders/api.py` 의 각 뷰에서 **표현만 떼어낸 것** —
  `orders.services` 를 부르고 `(verdict, outcome.state, {'order': order_json(order), 'refund': refund_json(refund)})` 를 돌려준다.
  `order_json`·`refund_json` 은 `orders/api.py` 것을 임포트해 재사용(콘솔·API·MCP 가 같은 표현). 권한·거부 문장은 `orders/api.py`
  와 글자까지 같게. `instructions` 는 `agent/prompts/ai_staff.md` 원문(임시 서버와 같은 이유 — 부채 리포트 입력).
  `approve_refund` 는 `perm='orders.change_refund'`, `forbidden_reason='AI 직원은 제안할 수 있지만 확정할 수 없다'`, 목록에 남긴다.
  `place_order` 의 `items` 해석은 `orders/api.py:_resolve_lines` 재사용. 실패는 `ToolDenied` 가 아니라 `ValueError` 문장 그대로
  올린다(400 에 해당 — 판정이 아니다).
- 마이그레이션: 패키지가 `django_itda/migrations/0001_initial.py` 를 갖고, 예시 프로젝트는 `migrate` 만 한다.
- `stages/live-실접속.md` (a) 절 뒤에 **(a') 패키지 경로** 절 추가: `claude mcp add itda-world-pkg --env WORLD_TOKEN=… -- uv --directory <예시 절대경로> run python manage.py mcp_stdio`.
  두 경로의 차이 한 문단 — HTTP 경로는 "LLM 은 월드 서버의 클라이언트" 의 물증, 패키지 경로는 같은 서비스 함수를 in-process 로
  부르며 **결과 모양이 하나**이고 **궤적이 admin 에 남는다**. 임시 서버는 지우지 않는다(8단계에서 대체).
- `justfile`: `mcp-pkg:` 레시피 (`uv run python manage.py mcp_stdio`).
- `tests/live_tools.py`(신규, 채점표 아님): `Toolset.call` 경로가 API 와 같은 판정을 내는지.
  1. `ai-staff` 로 `approve_refund` → `ToolDenied`, 문장에 "권한 없음".
  2. SEED-0001 `propose_refund` → `ToolDenied`, 문장에 `REFUND-001@v1`.
  3. SEED-0002 `propose_refund(request_id='k')` → `kind ESCALATE`·`outcome QUEUED`·`handle.check_tool == 'check_refund'`;
     **같은 키 재호출 → `outcome REPLAYED`**(발견 1 회귀); 다른 키 → `ALREADY`.
  4. `pay_order` on paid → `ToolDenied` `ORDER-001@v1`, 재고 불변.
  5. 위 호출마다 `ToolCall` 행이 생겼고 `via == 'mcp'`(Toolset 기본 via 는 호출자가 준다 — 테스트는 `via='mcp'`), 거부도 `error='denied'` 로 남는다.
  6. `check_refund` 는 거부된 건에도 예외 없이 결과를 준다.
