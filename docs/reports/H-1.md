# H-1 — django-itda: Django 6.1 · Python 3.14 지원 (v0.4.0)

- 날짜: 2026-09-19 · 브랜치: main(푸시·태그 안 함)
- 배경: itda-hub 를 Python 3.14 · Django 6.1 로 올리는데 `django>=5.2,<5.3` 이 해석을 막았다.
- 실측 버전: Python 3.12.14 / 3.14.7, Django 5.2.17 / 6.0.8 / 6.1.1, fastmcp 4.0.5, psycopg 3.3.6, PostgreSQL 17(alpine).

## 2. 6.1 에서 고친 것

**없음.** 근거:

- `django_itda` 전체(1,158줄)가 Django 6.1.1 · Python 3.14.7 에서 수정 없이 통과했다(아래 (b)).
- `-W error::DeprecationWarning -W error::PendingDeprecationWarning` 로 폐기 경고를 오류로 올려도 0건 — Django 의 `RemovedInDjango*Warning` 은 이 두 범주의 하위 클래스라 함께 잡힌다. 패키지는 `asyncio.iscoroutinefunction` 같은 폐기 API 를 쓰지 않는다(비동기 경계는 fastmcp 어댑터의 `sync_to_async` 뿐).
- `check --fail-level WARNING` 이슈 0, `makemigrations --check --dry-run` "No changes detected"(패키지·예시 둘 다).

## 3. 매트릭스 결과 원문

재현용 래퍼(스크래치, 저장소 밖)의 실제 명령 — `$PY`·`$DJ` 만 바뀐다:

```bash
# 패키지 (저장소 루트에서)
uv run --isolated --no-project --python "$PY" --with "$DJ" --with "fastmcp>=4,<5" \
  --with pytest --with pytest-django --with-editable . <명령>
# 예시 (examples/itda-django 에서)
uv run --isolated --no-project --python "$PY" --with "$DJ" --with "fastmcp>=4,<5" \
  --with "httpx>=0.28.1" --with pytest --with pytest-django --with-editable ../.. <명령>
```

## 4. 남은 경고

- **Postgres teardown 경고 1건**(위 (c) 패키지) — `test_시그니처에서_자리를_뗄_수_있다` 뒤 `test_itda` 삭제 시 다른 세션(어댑터 시험의 `sync_to_async` 스레드 연결)이 남아 있다는 `PytestWarning`. **6.1 회귀가 아니다**: 같은 명령을 Python 3.12 + Django 5.2.17 로 돌려도 똑같이 `88 passed, 1 warning` 이고, `docs/postgres-실측-2026-09-19.md` §2 에 이미 "별건"으로 기록돼 있다. 부작용으로 컨테이너에 `test_itda` DB 가 남지만 다음 실행이 지우고 다시 만든다.
- 그 밖의 경고 0(폐기 경고 오류화 상태에서 전 조합 통과, 시스템 체크 0).

## 5. 실행 못 한 것·범위 밖

- **CI 실제 실행** — 푸시 금지라 GitHub 에서 돌려 보지 못했다. 대신 `ci.yml` 의 명령을 로컬에서 네 칸 전부 그대로 돌렸다((d)). 액션 버전(`actions/checkout@v7`, `astral-sh/setup-uv@v10`)은 `gh api …/releases/latest` 로 확인한 최신 메이저다.
- **Python 3.13** — 로컬에 없어 돌리지 않았다. 분류자·표에는 "지원(CI 밖)"으로 둔다(Django 5.2·6.x 모두 3.13 지원).
- **Postgres 를 CI 에** 넣지 않았다(브리프 범위 밖, README 에 "로컬 `just test-pg`"로 명시).
- **컨테이너 정리** — `itda-django-pg` 는 이 작업 전(약 23시간 전)부터 떠 있던 컨테이너라 내가 띄운 것이 아니어서 내리지 않았다.
- **옛 표기 잔존(의도적으로 둠)** — 마이그레이션 헤더 `# Generated by Django 5.2.17`, `docs/구조-뒤집기-2026-09-06.md` 의 당시 `<5.3`, 리뷰·사양 문서의 "Django 5.2 `options.py`" 같은 과거 사실은 역사 기록이라 손대지 않았다. **루트 `CLAUDE.md`·`examples/itda-django/CLAUDE.md`·`examples/itda-django/docs/단계별-설계.md` 의 "Django 5.2 LTS" 스택 줄**은 하한 설명으로 읽혀 틀리지는 않지만, 규율 파일(CLAUDE.md)이라 빌더가 고치지 않았다 — 메인 세션이 "Django 5.2 LTS ~ 6.1" 로 고칠지 판단할 것.
