# Postgres 실측 (2026-09-19) — 고치기 전 목록

근거: [차용-검토-itda-django-bridge.md](차용-검토-itda-django-bridge.md) §1-4·§5(순서 재조정의 4번). 이 문서는 **고치기 전**의 원문 목록이다 — 무엇을 고칠지는 목록이 정한다.

## 환경

- 컨테이너 `itda-django-pg` — `postgres:17-alpine`, 127.0.0.1:55433, db/user/pw `itda`. `examples/itda-django` 에서 `just pg-up`(없으면 만들고 `pg_isready` 까지 대기)·`just pg-down`.
- 설정 — 예시 `examples/itda-django/probes/pg_settings.py`(`config.settings` 상속), 패키지 `tests/pg_settings.py`(`tests.settings` 상속). 둘 다 `DATABASES` 를 **통째로** 교체한다 — SQLite 전용 `OPTIONS`(`transaction_mode`·`init_command`)와 `TEST.NAME`(파일 경로)이 따라오면 재는 것이 PG 가 아니라 설정 찌꺼기가 된다.
- 실행 — 예시 `just test-pg`·`just migrate-pg`, 루트 `just test-pg`. psycopg 는 `uv run --with 'psycopg[binary]'` 로만 들인다(의존성 추가 없음).
- 기준선(SQLite): 루트 70 passed · 예시 137 passed.

## 1. 먼저 — `ledger/0002` 에서 migrate 가 깨진다

`just migrate-pg`:

```
Applying ledger.0002_append_only_trigger...
django.db.utils.ProgrammingError: syntax error at or near "BEGIN"
LINE 4: BEGIN
```

`CREATE TRIGGER … BEGIN SELECT RAISE(ABORT, …); END;` 는 SQLite 문법이다. `RunSQL` 에 vendor 가드가 없어 PG 에서는 **migrate 자체가 실패**하고, 따라서 테스트 DB 도 만들어지지 않는다(예시 테스트 전량이 시작 전에 멈춘다). 차용 검토 §1-4 (a) 의 예상이 사실로 확인됐다.

나머지 목록을 얻으려고 **커밋하지 않은 임시 우회**를 썼다 — `0002` 의 `RunSQL` 을 `RunPython`(vendor 가 `sqlite` 일 때만 `CREATE`/`DROP` 실행)으로 바꿔 한 번 돌리고 `git checkout` 으로 되돌렸다. 그래서 아래 표의 `test_장부는_고칠_수_없다_DB_층` 실패는 **우회의 결과**(PG 에 트리거가 없음)다.

## 3. 읽을 것

- **5단계 경합 시험은 PG 에서 전부 통과했다.** SQLite 에서 "세계가 막는다" 를 보인 시험들이 PG 의 행 잠금·READ COMMITTED 아래에서도 같은 판정을 냈다 — 차용 검토 §1-4 (b)·(c) 의 걱정은 이 시험 범위에서는 깨지지 않았다. 다만 `select_for_update` 가 **실제로 잠근다**는 것은 시험이 없고, 그 빈자리가 SQLite 전용 실측 시험(`has_select_for_update is False`)으로 남아 있다.
- 패키지 `busy.is_lock_failure` 는 SQLite 오류 코드·메시지만 안다. PG 의 잠금 실패(`55P03`·`40P01`·`40001`)는 `OperationalError` 로 오지만 판별이 `False` 를 돌려 `ToolBusy` 가 아니라 `exception` 으로 번역된다 — 목록에는 시험이 없어 드러나지 않았다. 이것이 커밋 2 의 몫이다.
