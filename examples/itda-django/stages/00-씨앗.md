# 0단계 — 씨앗

법이 없는 세계를 눈으로 본다. 이 단계에서 고칠 코드는 없다.

> 이 지시서는 `stage-00-done` 태그 상태 기준이다. 그때 `owner` 는 superuser 라 admin 에서 뭐든 할 수 있다.
> 1단계부터는 점주에게서 superuser 가 빠지고 계정이 하나(`admin`) 늘어난다. 아래 화면 실습은
> `git checkout stage-00-done` 상태에서 하고, 끝나면 `git checkout main` 으로 돌아온다.

## 준비

필요한 것: Python 3.12+, [uv](https://docs.astral.sh/uv/), [just](https://just.systems).

```bash
just setup
```

`uv sync` → `migrate` → `seed_world` 가 차례로 돌고, 마지막에
`세계 준비 완료 — 사용자 4명, 상품 6개, 주문 4건` 이 찍히면 세계가 선 것이다.

## 명령

```bash
just run
```

브라우저에서 <http://127.0.0.1:8000/admin/> 을 열고 `owner` / `owner1234` 로 로그인한다.
가게에 뭐가 있는지 한 바퀴 둘러본다.

1. **주문** 목록 — 4건. 상태가 결제 대기·결제 완료·배송 완료로 섞여 있다.
2. **상품** 목록 — 6개. 재고가 1개뿐인 상품이 하나 있다.
3. **환불** 목록 — 0건. 아직 아무도 환불을 요청하지 않았다.
4. **사용자** 목록 — 4명. `owner`·`ai-staff`·`alice`·`bob`.

그다음 이걸 해 본다.

- 배송 완료된 주문을 하나 열어 **상태를 `결제 대기`로 되돌린다**. 저장한다.
- 결제 대기 주문을 열어 **상태를 `배송 완료`로 건너뛴다**. 저장한다.
- 환불을 **직접 하나 추가한다**. 주문을 아무거나 고르고, 금액에 그 주문의 총액보다 큰 숫자를 넣는다. 저장한다.

## 의도적 실패

없다. **아무것도 실패하지 않는 것이 이 단계에서 볼 것**이다.

배송이 끝난 주문을 결제 전으로 되돌려도, 결제도 안 한 주문을 배송 완료로 만들어도,
주문 총액보다 큰 금액을 환불해도 세계는 아무 말이 없다. 저장 버튼은 매번 그냥 성공한다.

여기서 이 두 문장을 구별해 두자.

- 사람이 **말한 것**: "결제 안 한 주문을 배송 완료로 바꾸면 안 되죠."
- 세계가 **지키는 것**: (없음)

이 간극이 앞으로 아홉 단계 동안 다룰 전부다.

한편, 안 되는 것도 하나 있다. Django shell을 열어 재고를 음수로 만들어 보자.

```bash
uv run python manage.py shell -c "
from shop.models import Product
p = Product.objects.first()
p.stock = -5
p.save()
print('재고:', Product.objects.get(pk=p.pk).stock)
"
```

무슨 일이 일어나는지 기록해 둔다. 왜 이건 다르게 굴었는지는 3단계에서 다시 본다.
