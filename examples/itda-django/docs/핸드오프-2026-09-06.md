## 2. 확정된 결정 (재논의 금지)

- 세계 = "AI 직원을 고용한 점주의 가게". 관통 문장: **제안은 AI, 판정은 세계, 확정은 사람** + 보완 **"사람이 승인한 정책 범위는 규칙이 자동 확정하고, 격상 건은 사람이 확정한다"**(sol 리뷰로 추가 — 소액 자동 승인과의 모순 해소, 규칙 대장 출처=점주가 그 승인의 물증).
- 한 단계 = 법 하나(4단계는 법 3개 예외 — 단위가 "프롬프트 파일 하나"). 태그 `stage-NN-start/-done`, 코드 변경 없는 단계는 `-done`만. 히스토리 재작성 금지, 태그 이동은 `stages/README.md`에 기록.
- AI 직원은 고정 fixture(채점). 실접속은 관찰용 병행 트랙 — "LLM이 속는가"는 측정 대상이 아니다.
- Django 안에 MCP 호스팅 안 함(별도 프로세스 stdio). 근거: 저장소 루트 `docs/벤치마킹-MCP-생태계.md` — mcp v2(FastMCP 삭제), fastmcp 4.x 기반 권고 B-1, django-mcp-server(v1 고정·정지) 기각.
- "Django가 FastAPI에 밀리는 기능 종합 패키지"는 **명시적 비목표**. 대신 비교 가이드 문서 1편(미작성).
- 이사 비용표는 구현 diff / 준비 비용 분리, LOC는 효율 증명이 아님.
- **5단계 확정(2026-09-06)**: 승인 시점 기한 재검사는 **하지 않는다**(판정 시점 = 신청 시점, 바꾸려면 `REFUND-001@v2`). 같은 멱등키·다른 내용은 최초 내용 우선(충돌 검사 없음). DENY·ALREADY 는 저장하지 않는다. `select_for_update` 는 SQLite 에서 행 잠금이 붙지 않음을 실측만 한다. 경합 테스트는 `live_server` 가 아니라 **파일 테스트 DB + 스레드 + Barrier(잠금 밖, `mock.patch`)** 로 — 인메모리 shared-cache 에서는 잠금 오류가 먼저 난다. `IMMEDIATE`·WAL·timeout 은 빈도 완화이지 소거 증명이 아니다.
- 이름·배치: 도구면 패키지 **django-itda**(저장소 루트, 임포트 `django_itda`) / 교육 프로젝트 **itda-django**(`examples/itda-django/`). 별도 저장소는 사용자가 하나뿐인 지금은 이르다고 판단해 합쳤고(2026-09-06), 같은 날 저장소의 얼굴을 장기 자산인 패키지에 맞춰 구조를 뒤집었다 — `docs/구조-뒤집기-2026-09-06.md`.
- **구조 뒤집기 확정(2026-09-06 오후, 마스터 동의)**: 저장소 루트를 **패키지 django-itda** 로 올리고, 교육 프로젝트는 `examples/itda-django/` 아래로 내린다. 저장소 이름도 같은 날 `django-itda` 로 바꾼다(루트와 이름이 어긋난 상태를 남기지 않는다). 시점은 **실접속 관찰 기록 커밋 직후, django-itda 첫 코드 직전** — 이동 커밋은 `stage-05-done` 과 `stage-06-start` 사이에 놓고 `stages/README.md` 에 경로 불연속을 기록한다(히스토리 재작성 아님, 태그 ≤05 는 루트 레이아웃 그대로). 교육 규율(한 단계 = 법 하나·RULES append-only·태그)은 예시 디렉터리의 CLAUDE.md 로 내려가고, 루트 CLAUDE.md 는 패키지 정체가 된다. 종전 "두 번째 사용자 시점에 디렉터리째 분리" 계획은 이 결정으로 폐기.

## 4. 작업 규율 (이 저장소에서 지킨 것)

- **7단계 실측(2026-09-07)**: 독립 검증 20/20 PASS 뒤에도 sol 이 높음 1·중간 6 을 찾았다 — 검증은 사양이 시키는 것을 재현하고, 리뷰는 사양 밖 반례(같은 상품 두 품목·캐시 상태·SET_NULL↔트리거·역마이그레이션·채점표에 오류 주입)를 만든다. **둘 다 한다.** Codex 는 긴 프롬프트가 TUI 에 안 들어가므로 프롬프트 파일 경로를 읽게 한다. pane 세션은 지시에 "rm 금지" 를 넣어도 `rm` 을 써서 삭제 가드에 두 번 걸렸다 — 마스터가 pane 에서 `1` 을 눌러 풀었다(자동 응답 금지 유지).
- **2026-09-07 부터 빌더·검증은 Herdr sibling pane 의 별도 Claude 세션**(`herdr agent start <이름> --kind claude --pane <ID> -- --model opus --dangerously-skip-permissions`, 프롬프트는 스크래치패드 파일로, `herdr agent wait` 로 대기). 서브에이전트는 진행이 안 보여 마스터 지시로 전환. `blocked`(삭제 가드 `rm`·`curl` 확인 규칙)면 화면을 읽어 마스터에게 묻고 자동 응답하지 않는다. **독립 검증**은 구현자 보고를 주지 않고 사양서만 준 세션이 worktree·별도 DB(`ITDA_DB`)·다른 포트로 직접 움직여 "주장→증거→판정" 표를 낸다(6단계 실측: 20항목, 낮은 우려 3 → 수정 라운드 → done 태그는 수정 커밋에).
- 구현은 전부 `.claude/agents/app-builder.md`(Opus·medium)에 위임. 메인 세션은 사양·검토·결정만. 빌더 보고의 "설계와 달리 판단한 지점"을 반드시 읽고 동의/기각을 기록.
- 리뷰 파이프라인: 심장 단계(4·5 완료, 앞으로 7)는 완료 후 Codex(sol) 적대 리뷰 1라운드 → fable 비판 재검토 → `docs/reviews/`에 원문+반영 결정표 커밋 → 수정 라운드 → 태그 부착/이동. Codex 기동 시 "디렉터리 신뢰" 프롬프트는 자동 응답하지 않고 사용자에게 묻는다(5단계 실측 — 경로가 바뀌면 다시 뜬다). 리뷰 프롬프트는 "4단계에서 예약한 항목이 실제로 해결됐는가"를 첫 질문으로. Herdr 세션(`HERDR_ENV=1`)이면 리뷰는 sibling pane에서(`.claude/rules/herdr-visible-background.md`). Codex 모델이 용량 초과로 끊기면 "계속하라 — 추가 탐색 없이 결론만" 재프롬프트로 회수 가능.
- 삭제 가드: 저장소 밖 `rm` 차단됨 — 옮길 땐 `mv`로. 빌더가 "대신 지워 달라"고 하면 가드 우회이므로 하지 않고 사용자에게 보고.
- 이전 단계 코드를 고칠 때 태그는 옮기지 않고(0단계 seed 테스트 수정 사례) 지시서에 주석. 단, 리뷰 반영은 학생 diff에 포함돼야 하므로 `-done` 이동.
- 빌더 검증 결과는 메인 세션이 `uv run pytest`로 항상 재실행해 확인.
