- **작성**: 2026-09-05 · **상태**: 확정 설계 (마스터 동의 2026-09-05), 구현 진행 중
- **출처 논의**: hyve-training `docs/논의-실행세계-안건1-어떤-세계.md` · `안건2-Django의-가치.md` · `저자포스팅-점검-고정파이프라인.md` · `커리큘럼-AI-실행세계-Django.md`(v3)
- **비교 물증**: `~/Temp/test-django`(orca-mall, 태그 `edu-intentional-defect-v0`) — 완성형. 이 저장소는 그 코드를 단계에 맞게 **수확**해 0단계부터 앞으로 짓는다.

## 0. 세계 한 문장

> **"AI 직원을 고용한 점주의 가게"** — AI가 주문·환불을 *제안*하고, 가게의 법(불변식·전이 계약·격상 임계)이 *판정*하고, 점주(학생)가 admin 승인 큐에서 *확정*한다.

관통 논지 **제안은 AI, 판정은 세계, 확정은 사람**. 한 겹 보완(2026-09-06, sol 리뷰): **사람이 승인한 정책 범위는 규칙이 자동 확정하고, 격상 건은 사람이 확정한다** — 소액 자동 승인(`decided_via='rule'`)이 "확정은 사람"과 어긋나지 않는 이유는, 그 범위를 정한 것이 점주이기 때문이다. 그 승인의 물증이 `RULES.md`의 **출처** 열이고, 출처가 없으면 배후의 사람이 사라진다. Django의 역할: *법을 써주지 않는다. 선언한 법을 대신 지켜주고, 선언할 자리를 준다.* 범용 법(정체성·관제·선언적 제어·이력)은 기본값, 도메인 법(7일 환불·5만원 격상·pending→paid만)은 학생이 이사시킨다.

## 1. 원칙

1. **한 단계 = 법 하나.** 범용 법 하나를 인식하거나 도메인 법 하나를 이사시킨다. 단계 간 코드 diff는 학생이 한 번에 읽을 크기(~200줄 이내).
   - **5단계도 예외** — 법은 하나(`REFUND-003@v1`)인데 앱 코드 +368 −61 로 4단계와 비슷하다. 시행 면이 셋(DB 제약·전이 계약·멱등키)이라 부르는 쪽 세 곳(콘솔·admin·API)이 함께 바뀌고, 잠금 실패 번역(미들웨어)이 따라붙기 때문이다. 준비 비용은 더 커서 +1054 다 — 경합은 "그냥 두 번 호출"로는 관찰되지 않아 파일 테스트 DB·Barrier 헬퍼·`just race` 명령이 함께 필요하다.
   - **4단계는 의도적 예외** — 법 3개(`REFUND-001`·`REFUND-002`·`ORDER-001`), 앱 코드 +376 −61. 이사 실습의 단위가 "법 하나"가 아니라 **"프롬프트 파일 하나"**이기 때문이다. 세 문장이 한 파일에 함께 있고, 셋 중 하나만 옮기면 "프롬프트에 남은 문장은 여전히 안 지켜진다"는 대조가 흐려진다. 1단계(+661)도 0단계 위에 콘솔·격상을 한꺼번에 얹느라 이 크기를 넘는다.
2. **시작 상태와 완료 상태가 둘 다 존재.** 태그 `stage-NN-start`(다음 실패가 준비된 결함 있는 세계) / `stage-NN-done`. `git diff stage-NN-start stage-NN-done`이 정답 해설.
3. **실습 형식** = `준비 → 명령 → 의도적 실패 → 수정 → 검증 → 제출물`. 각 단계 폴더 `stages/NN-<이름>.md`가 학생용 지시서.
4. **테스트가 채점표.** 완료 상태에서만 통과하는 테스트를 단계마다 심는다(`tests/stage_NN_*.py`). 시작 상태에서는 그 테스트가 **실패해야** 한다(실패 자체가 "보장 부재"의 결정적 재현).
5. **AI 직원은 고정 fixture.** 실제 LLM 호출 없음 — 시나리오별 고정 제안(악성 응답 포함)이 서버 API를 호출한다. 확률적 데모 금지(모델이 버티면 "프롬프트로 충분"이라는 역교훈). 실제 LLM 연결은 비채점 보너스.
6. **한 저장소, 선형 히스토리.** 단계 디렉토리 병렬 배치(stage01/, stage02/…) 금지 — 중복·전파 실패. 태그 + `just stage NN` 체크아웃.

## 2. 기술 스택 (고정)

- Python 3.12+, **uv**, Django 5.2 LTS, SQLite, 기본 템플릿(Tailwind CDN 정도만, JS 빌드 없음)
- dev: pytest + pytest-django, ruff. 8단계 전까지 외부 서비스 0.
- 앱: `accounts`(AbstractUser 최소 커스텀), `shop`(Category·Product), `orders`(Order·OrderItem·Refund), `agent`(AI 직원 콘솔 + fixture 시나리오). 5단계 이후 `ledger`(감사·궤적), 8단계 `tools`(MCP).
- 계정 2개 seed: `owner`(점주, is_staff, 승인 권한) · `ai-staff`(AI 서비스 계정, 제안 권한만). 요청자≠승인자를 계정으로 물리화.

### 6단계 행 정정 (2026-09-07) — 원문은 위에 그대로 둔다

위 표의 6단계 행에 적힌 **"상품 설명에 주입 페이로드 seed → fixture AI 가 지시를 따라
`/api/orders/` 호출 → 자기 주문만"** 축은 6단계에서 **뺀다**. 근거는
[`docs/사양-06-주체.md`](사양-06-주체.md) §8(마스터 논의 2026-09-07).

- 그 축의 주체는 "AI 직원이 **지금 누구를 대신하는가**"(대행 스코핑)인데, 이 세계의
  AI 직원은 가게 직원이라 모든 주문을 보는 것이 자리에 맞고, 대화별 대행 주체는
  아직 세계에 없다. 없는 것을 뚫어 놓고 막는 실습이 된다.
- 6단계의 주체는 **고객**이고, 그 첫 문이 **결제 페이지**다. 결제는 돈을 내는 사람의
  확정이라 AI 직원이 대신 누를 일이 아니다 — 관통 문장의 "확정은 사람" 에서
  **확정하는 사람이 둘**이 되는 자리다(환불은 점주, 결제는 고객).
- 그래서 6단계의 법은 **둘**이다: `PAY-001@v1`(결제 링크 발급 + 서명 토큰 1시간 만료,
  `PasswordResetTokenGenerator` 서브클래스)과 `SCOPE-001@v1`(결제 페이지의 소유권
  스코핑 — 남의 주문은 **404**). "한 단계 = 법 하나" 의 예외이고, 단위는
  **"결제 페이지 하나"** 다(4단계의 "단위 = 프롬프트 파일 하나" 와 같은 격).
- 대행 스코핑과 주입 재현은 **8단계 세계 부채 리포트의 입력으로 이월**한다.
  `SCOPE-001@v1` 은 대장에 오른 첫 **부분 이사**이고(고객 문에서만 지켜진다),
  프롬프트 6번의 이사 표시에 `미이사` 가 그대로 적혀 있다.

시작 상태 결함도 그에 맞게 바뀐다: 상품 설명의 주입 페이로드가 아니라
**주문자 검사가 없는 결제 페이지 + 만료 없는 링크**다.

## 3-1. 실접속(live) 트랙 — 진짜 Claude를 세계에 붙이기 (2026-09-06 추가)

- **시점**: 4단계 완료 직후 개시, 이후 5~8단계 지시서마다 "실접속으로 같은 것을 보기" 절을 병행. 4단계 전에는 전이 계약이 없어 실제 LLM을 붙이지 않는다(무방비 세계).
- **구조**: 별도 프로세스 MCP 서버(stdio 우선, Claude Desktop/Claude Code 등록 한 줄)가 `ai-staff` 토큰으로 Django의 **인증된 뷰**를 호출하는 얇은 클라이언트 — "LLM은 월드 서버의 클라이언트"를 구조로 보인다. Django 안에서 MCP를 호스팅하지 않는다(v3 §4·8단계 심화 소재).
- **채점과 분리**: 채점은 고정 fixture(원칙 5), 실접속은 관찰용. Claude가 `approve_refund`를 부르면 fixture와 같은 403/ESCALATE.
- **패키지**: 도구면은 저장소 루트의 `django_itda`(실행세계 도구면 패키지 django-itda — 2026-09-06 별도 저장소에서 편입, 같은 날 구조 뒤집기로 저장소 루트가 되었다 — ESCALATE 응답·궤적 기록·권한=법)가 제공하고, `examples/itda-django/` 가 그 첫 사용자. 패키지 완성 전에는 `agent/live/mcp_server.py` 임시 구현(FastMCP + httpx).
- **Django 측 필요물**: `ai-staff` API 토큰 모델·인증, 콘솔 4비트와 동일한 JSON 뷰. ChatGPT(원격 Streamable HTTP + OAuth)는 부록.
- **임시 구현 완료 (2026-09-06, `8490c68` Django API · `2f04e75` MCP 서버 + 안내서 커밋)** — `accounts.APIToken`(sha256 해시 저장) + `orders/api.py`(콘솔과 `orders/services.py` 공유) + `agent/live/mcp_server.py`(fastmcp 4.0.3 · stdio · 도구 7개). 등록·관찰 절차는 [`stages/live-실접속.md`](../stages/live-실접속.md). 도구면은 **django-itda 로 추출 예정**이며, 추출 후 이 파일은 8단계의 "선언에서 도구면 생성" 코드로 대체된다.

`stages/README.md`에 단계마다 기록. **두 축을 분리**한다(2026-09-06 sol 리뷰 반영):

- **구현 diff** (`stage-NN-start`→`stage-NN-done`, 앱 코드 = `*.py`·`*.html` − `tests/` − `migrations/`) — 학생이 쓰는 코드.
- **준비 비용** (`stage-(NN−1)-done`→`stage-NN-start`) — 교재 쪽이 미리 까는 테스트·지시서·시작 상태 fixture. 학생 diff엔 안 보이지만 없으면 단계가 성립하지 않는다.

집계는 `git diff --numstat` + awk 분류로, **재현 명령을 표 아래에 함께 싣는다**(손으로 센 값 금지). 0~3단계는 사후 산출. 4단계에서 "프롬프트 한 줄 → 코드"의 실제 비용(안건2 ③ 원가표)을 실측으로 채우고, 8단계 끝에 "세계 하나 = 총 N줄" 결산. **LOC는 변경량이지 시간·유지비·효율의 증명이 아니다** — 표에 "그래서 싸다/효율적이다"를 쓰지 않는다. 보장 범위는 줄 수가 아니라 `RULES.md`의 "적용 경로 / 우회 가능 경로" 열이 답한다.

## 4. 저장소 규약

- 태그: `stage-NN-start`, `stage-NN-done`. 한 단계 완료 = 두 태그 + `stages/NN-*.md` + 테스트.
- 이전 단계 코드를 고칠 일이 생기면 **최신 커밋에서 고치고 태그를 재지정**한다(히스토리 재작성 금지, 태그만 이동). `stages/README.md`에 태그 이동 이력 기록.
- `justfile`: `just setup`(uv sync·migrate·seed) · `just stage NN` · `just test NN` · `just reset-db`.
- 규칙 대장 `RULES.md`: append-only. 행 = ID(`REFUND-001@v1`)·원문·출처·시행 형식·코드 위치·검증 테스트. 삭제 불가, `deprecated` + 후속 버전만.

## 5. 구현 순서

0 → 1 을 먼저 완주해 "1일차 무코드 체험"이 실제로 성립하는지 확인한 뒤 2~4를 잇는다. 4단계(규칙의 이사)가 과정의 심장이므로 4 완료 시점에 sol 리뷰 1라운드.
